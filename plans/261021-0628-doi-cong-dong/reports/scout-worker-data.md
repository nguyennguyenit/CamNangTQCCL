## 1. Migrations
- 0001 = Better Auth tables (`user`, `session`, `rateLimit`, …). No `uploads` FK anywhere: grep `references uploads` in `migrations/` returns nothing. VERIFIED.
- 0002_community.sql: `comments` (l.4-14: `page_key`, `lang in vi/zh`, `user_id` FK cascade, `body`, `created_at` ms; idx `(page_key,lang,created_at desc,id desc)`); `uploads` (l.17-27: `kind check in ('report','post')`, `object_key unique`, `status check in ('pending','attached')`, idx `uploads_status_created_idx`); `battle_reports` (l.30-50: `page_key`, `lang`, `user_id` cascade, `image_key`, `result`, `ally_heroes`/`enemy_heroes` JSON text, `note`, `season text` null, `status`, `reject_reason`, `reviewed_by`(no FK), `reviewed_at`, idx page/lang/status/created, page/status, status/created, user/created); `posts`; `rate_limits(key pk,count,expires_at)`.
- 0003 feedback; 0004 recruit_records; 0005 scan_stats/scan_samples (FK `reviewed_by ... on delete set null`). Pattern for new tables: `text pk`, `created_at integer` ms, status check constraint, `user_id ... references "user"("id") on delete cascade`, comments in Vietnamese.
- 0006_user_admin.sql: `alter table "user" add column ...` (role, banned_until, ban_reason, banned_by, banned_by_role, deleting_at, last_seen_at); `admin_audit` table (l.12-28); indexes `uploads_user_idx` (l.32), `scan_samples_user_idx`, `feedback_user_idx`; 4 `before insert` triggers on session/uploads/battle_reports/scan_samples raising `account_blocked` using DB clock `unixepoch('subsec')*1000` (uploads trigger l.44-50, battle_reports l.52-58).
- **No migration so far has ever altered a CHECK constraint or rebuilt a table**: only `create table`, `create index`, `alter table add column`, `create trigger`. VERIFIED (read all of 0002-0006).
- SQLite cannot ALTER a CHECK. Adding `'team'` to `uploads.kind` requires a table rebuild (create new, copy, drop, rename) [INFERENCE from SQLite semantics; no precedent in repo]. A rebuild drops: trigger `uploads_block_blocked_user`, indexes `uploads_status_created_idx` + `uploads_user_idx`, unique `object_key`; must recreate all. Nothing references `uploads` by FK so FK risk is nil, but D1 runs with FK enforcement and `uploads.user_id` FK->user must be kept in the new table. **Cheaper alternative: reuse `uploads.kind='report'`** (the AI analyze flow is identical, only the `/api/reports/analyze` AI route differs) or create a new `team_images` table instead of touching `uploads`. Note: `kind='report'` is also what `inventoryKeys` deletes (users.ts:367) — so reusing 'report' gives account-delete cleanup for free; a new kind needs inventory update (see §5).
- Rollback convention: `rollback/0007_drop_user_block_triggers.sql` — lives OUTSIDE `migrations/` so `wrangler d1 migrations apply` ignores it; header comment explains manual run `npx wrangler d1 execute tqccl-community --remote --file rollback/...`; uses `drop ... if exists`; leaves added columns/tables in place (old Worker ignores). Numbering continues next free number (0007 used by rollback file; next migration would be `0007_*.sql` — number clash with the rollback filename is cosmetic, they're in different dirs) [INFERENCE].
- A new team table that needs the "blocked user" guard should add its own `before insert` trigger copying 0006 l.44-50 (pattern doc: docs/community-worker.md:211 states only tables holding R2 keys/sessions have triggers; comments/feedback/recruit only have guards).
- wrangler `migrations_dir: "migrations"`, scripts `db:migrate:local|remote` (package.json:24-25; wrangler.jsonc d1_databases).

## 2. Upload flow
- Only one pipeline creates `uploads` rows besides posts:
  - `POST /api/reports/analyze` (routes/reports.ts:90-135): requireUser → FEATURE_ENABLED kill-switch 503 `feature_disabled` (l.92) → `resolveRoute(loadAiConfig(AI_KV,AI_CONFIG_SECRET),"battleReport")`, 503 `ai_not_configured` if no targets (l.95-96) → `parseImageUpload(req,"image",1_500_000)` → `consumeRateLimit("analyze")` (20/day) → R2 put `pending/<uploadId>` with `customMetadata.userId` (l.102-107) → D1 `insert into uploads (...,'report',...,'pending')` (l.109-113; on failure R2 delete, l.116) → `analyzeReportImage` (analyze.ts, 164 lines, not read in detail). ModelError 422 -> empty analysis and keep upload; other model errors delete R2+upload row and rethrow (l.126-132). Returns `{uploadId, analysis}`.
  - `POST /api/admin/uploads` (routes/posts.ts:338-371): `kind='post'`, key `posts/<id>.<ext>`, inserted already `attached`.
- Attach: `POST /api/reports` (reports.ts:137-183) selects upload `where id=? and user_id=? and kind='report' and status='pending'` (l.151-155), reads R2, rate-limit `report` (30/day), puts final `reports/<id>.<ext>` (l.163-167), `db.batch([insert battle_reports..., update uploads set status='attached', object_key=? where id=?])` (l.169-175), on batch error deletes the new R2 key (l.178), finally deletes the `pending/` object (l.181).
- R2 key layout: `pending/<uploadId>`, `reports/<id>.<ext>`, `posts/<id>.<ext>`, `scan-samples/<id>.<ext>` (scan.ts:215). Doc at docs/community-worker.md:21.
- Cron `cleanup.ts:8-26` (wrangler `17 * * * *`): lists R2 prefix `pending/` older than `PENDING_TTL_MS`=24h, deletes; then `delete from uploads where status='pending' and created_at < cutoff` and expired rate_limits. Works for any kind (no kind filter) → a new `pending/` kind is cleaned automatically. VERIFIED.
- validate.ts: `IMAGE_TYPES` jpeg/png/webp (l.82-86); `sniffImageType` magic bytes (l.89-96); `parseImageUpload(req, field, maxBytes)` (l.105-129): content-length pre-check (+64KB multipart slack), multipart only, one field, declared MIME must equal sniffed, 413 `image_too_large`, 415 `invalid_image_type`, 400 `missing_image`. **Single-file parser** — 1-3 images in one request needs a new parser or 1 upload per image (each = 1 `uploads` row, consumes `upload` rate-limit? see below).
- Rate limit key `upload` exists in RATE_RULES (ratelimit.ts:18, 100/day) but grep shows the analyze flow uses `analyze`, not `upload`; I did not find `consumeRateLimit(...,"upload"...)` in routes read (posts.ts admin route not checked for it) [INFERENCE: `upload` may be unused or used by posts].
- Image serving pattern: reports.ts:217-244 `GET /api/reports/:id/image` — visibility = approved && author visible; else owner/staff only; 404 not 403; `Cache-Control: public, no-cache` / `private, no-store`, `X-Content-Type-Options: nosniff`, ETag/304 handling AFTER auth. Copy for team images.

## 3. battle_reports flow & what must change
- PAGE_KEY_RE = `/^\/(doi-chuan|doi-khac|khai-hoang)\/[a-z0-9][a-z0-9-]{0,120}\/$/` (validate.ts:5), used by `parsePageKey` (l.16-21) which is called in: reports POST (l.140), GET list (l.186), stats (l.198), comments GET/POST (comments.ts:53,75). **`/doi-cong-dong/<id>/` is rejected (400 `invalid_page`) everywhere until the alternation is extended.** Team ids from `newId()` = `crypto.randomUUID()` (app.ts:25) match `[a-z0-9-]` so the regex fits; the test harness id `id-0001` also fits.
- Create: reports.ts:137-183 (above). It trusts `season` from client (`parseOptionalText(input.season,"season",40)`, l.147) and does NO existence check of the page. For community pages must add: lookup team by id from page, require `status='approved'` and team author visible, reject own-team? (not required), and `season` must equal `open_season` else 409 `season_closed`; set `season` server-side from the team row [INFERENCE for design].
- `lang` is NOT NULL vi/zh on report rows and `GET /api/reports` requires `lang` and filters `r.lang = ?` (l.186-193) — for the shared pool, list for community page must skip the lang filter or the client must request both. `GET /api/reports/stats` already ignores lang (l.197-206).
- Public list query: where `r.page_key=? and r.lang=? and r.status='approved' and visibleUserSql("u")` binds `[page, lang, now]` (l.189-193). `visibleUserSql(alias)` = `(a.banned_until is null or a.banned_until <= ?) and a.deleting_at is null`, one bind = now (moderation.ts:34-36).
- Admin: `GET /api/admin/reports?status=` (requireStaff, l.252-260) lists with no visibility filter; `review()` (l.263-299): requireStaff; `select user_id,page_key`; **single `DB.batch([update battle_reports set status,reject_reason,reviewed_by,reviewed_at where id=?, auditIfStmt(...)])`**; audit written only if `select 1 from battle_reports where id=? and status=? and reviewed_by=? and reviewed_at=?` matches (proof the same UPDATE ran) (l.273-296); 404 when `res.meta.changes==0`. Actions `report.approve`/`report.reject`, `targetType:'report'`, `targetLabel: page_key`, `subjectUserId` = author. Reject requires reason 1-500 (l.303-307). No notion of season/state transitions (re-approve of already-approved allowed).
- Scoring "distinct non-author users with ≥1 approved winning report": all pieces exist (`battle_reports.result`, `status`, `user_id`, visibleUserSql); need a new query `count(distinct r.user_id) ... where page_key=? and status='approved' and result='win' and r.user_id <> team.author_id and visibleUserSql("u")`. Existing `aggregateStats` (stats.ts:32-64; counts total/wins/losses/draws, winRate, topOpponents) can be reused as-is for the stats panel; it does not compute distinct users.
- Note: when the team author is deleted, `battle_reports.user_id` cascade only deletes the REPORTER's own rows; reports for a deleted team page_key remain orphaned (page_key is plain text, no FK) [INFERENCE] → delete-team (author delete or account deletion) should also delete `battle_reports where page_key='/doi-cong-dong/<id>/'` + their R2 images, and comments for that key.
- Frontend admin audit labels live in `js/community-admin-users.js:29-48` (`actionLabel` switch + `AUDIT_ACTIONS` list l.53-57); each new audit action needs vi/zh label there + test e2e.
- Admin badge counts: routes/admin.ts:15-21 `COUNTS_SQL` (single select of subqueries) + response keys (l.28-34) → add `teamsPending`.

## 5. Account deletion
- `DELETE /api/admin/users/:id` (users.ts:~379-480, `requireRoot`): step 1 mark `deleting_at` + audit `user.delete.start` + kill sessions in one batch (l.~397-415); step 2 `inventoryKeys()` (users.ts:363-377) = `uploads where user_id=? and kind='report'` ∪ `battle_reports.image_key` ∪ `scan_samples.image_key` (deliberately excludes `kind='post'`), deleted from R2 in chunks `R2_DELETE_CHUNK`; R2 failure → audit `user.delete` failed + 502 `delete_incomplete`, retryable; step 3 counts + final batch: audit(`user.delete`, meta objects/comments/reports/scanSamples/feedback) → reassign post uploads to actor → null out `posts.author_id`, `feedback`, `battle_reports.reviewed_by`, `scan_samples.reviewed_by` → `delete from "user"` (FK cascade removes comments/uploads/battle_reports/scan_samples/recruit etc.).
- **Must change**: add team image keys to `inventoryKeys` (new `select image_key ... from team_images/teams where author_id=?` queries) and, if teams/votes reference users, set `reviewed_by = null` for team moderation columns (as done for battle_reports/scan_samples, l.~117-118 of the stmts array), keep audit meta counts (add `teams`). New tables referencing `"user"` should use `on delete cascade` (votes, teams) so the final DELETE works; any `reviewed_by` w/o FK or with set null is fine but a cascade-less FK to user without null-out would make DELETE fail [INFERENCE].
- Also: reports/comments on the deleted user's teams (page_key text) won't cascade — see §3. Test precedent: test/users.test.ts:560-663 seeds R2 keys `reports/r1.png`, `pending/up2`, `scan-samples/s1.png`, `posts/keep.png` and asserts exactly which keys are deleted (`deleted.sort()` equality at l.663) → must be updated for new keys.

## 7. ratelimit / audit / http
- `RATE_RULES: Record<string,{limit,windowMs}>` (ratelimit.ts:14-27): comment 10/h, analyze 20/d, report 30/d, upload 100/d, feedback_anon 5/h, feedback_user 10/h, scan_stats 60/h, scan_sample 10/d, recruit_push 600/h. Add a key there (e.g. `team_post`, `team_vote`, `team_analyze`) and call `await consumeRateLimit(c.env.DB, "<key>", user.id, now)`; counter key `<action>:<userId>:<windowStart>`; over limit → ApiError 429 `rate_limited` + Retry-After (l.30-45). Unknown action key would throw TypeError (RATE_RULES[action] undefined) → must add before use. Counter counts even rejected attempts.
- Errors: `throw new ApiError(status, code, message[, retryAfter])` (http.ts:3-12); `app.onError` maps to `{error:{code,message}}` (app.ts:34-42); validators in validate.ts throw 400 `invalid_<field>`. Existing conflict codes: 409 `user_banned`, `image_missing`, `not_approved`; use 409 `season_closed` per requirement. Cursor pagination `encodeCursor/decodeCursor/paginate` is `(created_at,id)` only (http.ts:21-73) — Hot/Top sort by score needs a different cursor (offset or (score,created_at,id)) [INFERENCE]. `iso(ms)` helper.
- Audit: `admin_audit` row builders `auditStmt`, `auditIfStmt(c, viewer, entry, existsSql, binds)`, `writeAudit`, `writeAuditQuietly` (audit.ts:57-87). Actor must be root/moderator else throws (l.35). Action naming: lowercase dot-separated `<entity>.<verb>` (`report.approve`, `scan_sample.reject`, `comment.delete`, `user.delete.start`, `post.publish`, `ai.config.update`); read-API regex `^[a-z_]+(\.[a-z_]+){0,3}$` max 40 chars (routes/audit.ts:37-49). `targetType` singular entity (`report`,`comment`,`user`). Suggested: `team.approve`, `team.reject`, `team.delete` (staff) and `season.open` (settings), `targetType:'team'/'setting'`. Audit pattern for moderation: UPDATE first, audit after with exists-proof; for deletes audit BEFORE delete with guard (comments.ts:118-134).
- Admin routes mount in app.ts:92-101 (`app.route("/", x)`); `/api/*` middleware does CSRF origin check on non-GET and sets `Cache-Control: no-store` default (app.ts:53-64). Role helpers: `requireUser/requireStaff/requireRoot`, `effectiveRole` (context.ts:62-80). Admin `open_season` setting: no settings table exists; options: new `app_settings(key,value)` table via migration, or KV (AI_KV is shared/encrypted) [INFERENCE]. `season` free text ≤40 in battle_reports.

## Implications for the plan
- Migration `0007_community_teams.sql` (new; `rollback/` note if it adds a user-blocking trigger): tables `community_teams` (id, author_id→user cascade, season, hero/tactic ids JSON or columns, troop, analysis text cols, lang_of_text, image keys or separate `community_team_images`, status pending/approved/rejected, reject_reason, reviewed_by/at, created_at), `community_team_votes` (team_id, user_id, value ±1, unique(team_id,user_id), FK cascade), `app_settings` for `open_season`; indexes for (status,season,created_at) and score sorting; copy the `before insert` blocked-user trigger (0006 l.44-50) for the teams table (it holds R2 keys).
- Avoid rebuilding `uploads`: reuse `kind='report'` for pending team images (inventoryKeys then already covers `pending/`), or add a dedicated image table; if `'team'` is truly required, a rebuild must recreate trigger `uploads_block_blocked_user`, indexes `uploads_status_created_idx`, `uploads_user_idx`, unique `object_key`.
- Files to modify: `src/validate.ts` (PAGE_KEY_RE + shared helper `COMMUNITY_PAGE_RE`, team/hero id parsers, multi-image parser), `src/routes/reports.ts` (team existence + season-open check for community page, lang handling in list, server-set season), `src/routes/comments.ts` (drop lang filter for community namespace), `src/routes/users.ts` (inventoryKeys, counts meta, null-out reviewed_by, delete comments/reports for owned team page_keys), `src/ratelimit.ts` (new keys), `src/routes/admin.ts` (teamsPending count), `src/app.ts` (mount new router), `src/stats.ts` (distinct-winner score helper), `js/community-admin-users.js` (audit labels + AUDIT_ACTIONS + pagePath), `docs/community-worker.md`, `test/fakes.ts` (ApiJson fields), `test/users.test.ts`, `permissions.test.ts`, `visibility.test.ts`, `tests-e2e/community.spec.mjs` mock.
- New files: `src/routes/teams.ts` (create/list/detail/vote/delete/similar/image/analyze/admin review/open-season), `test/teams.test.ts`, migration.
- Patterns to copy: upload+attach flow reports.ts:90-183 incl. R2 compensating delete; image route reports.ts:217-244; moderation batch+`auditIfStmt` reports.ts:263-299; cleanup/cron untouched.
- Risks: (1) shared `parsePageKey` change affects 3 routes — keep `/doi-cong-dong/` only for comments+reports; (2) orphan reports/comments/R2 when a team is deleted (no FK on page_key) → delete in same batch; (3) cursor pagination is time-based only, Hot/Top need new cursor design; (4) fake D1 `batch` is real sqlite so triggers/FK enforce in tests but D1 `defer_foreign_keys`/batch semantics are only approximated [INFERENCE]; (5) `battle_reports.lang` NOT NULL — community reports still need a lang; (6) race: season closing between check and insert (use `insert ... select ... where exists(open_season = team.season)` inside the batch for vote/report inserts); (7) multi-image upload: validate.ts parses a single file; (8) `analyze` limit is shared 20/day by key `analyze`; a team prefill should likely reuse it or add `team_analyze`.
