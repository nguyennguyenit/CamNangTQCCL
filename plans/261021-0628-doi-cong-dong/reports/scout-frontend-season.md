Scope: read-only. VERIFIED = read in repo; INFERENCE = my deduction.

## 1. Season identity

VERIFIED
- No canonical "season" list with vi+zh labels exists. `data/season-registry.json` is an array of `kind:"scenario"` records with only `id`, `labelVi`, `region`, `reviewStatus`, `rulesets` (empty), `sourceMappings` — **no `labelZh`**. Only 2 entries today: `anh-hung-menh-the` ("PK-S26 · Anh Hùng Mệnh Thế"), `binh-dien-xuan-thu` ("OG · Binh Diễn Xuân Thu") (data/season-registry.json:9 and python dump).
- Season-context machinery (`js/season-context.js`) is a validator for the 5-artifact "season bundle" (`ARTIFACTS`, `DATASETS`, js/season-context.js:4-5); `compareSeasonIds` is only a code-point string comparator for sorting ids (js/season-context.js:~96-104). It owns no season list/UI. Browser adapter: `js/season-ui-state.js` (`SEASON_ARTIFACTS` :6, `loadSeasonModel` :9, reviewed ids :24). It requires 10 hash-pinned artifacts — far too heavy for a community page.
- `data/teams.json` (166 teams) has no `season` field (counter → all `None`). Team detail slugs embed a season prefix (e.g. `pk-s24-tu-ma-phi-hung`, tests-js/pages-headers-contract.test.mjs:~108) — format `pk-sNN-…`, `sNN-…` in recommended scope keys (pipeline/site-translations.json entries `…/s23-diyu-fugui-1`). [INFERENCE: those prefixes are not a stable registry.]
- Client never sends `season` for battle reports: `js/community-reports.js` POST body is `{ page, lang, uploadId, result, allyHeroes, enemyHeroes, note? }` (js/community-reports.js:~232). Worker accepts optional free text `parseOptionalText(input.season,"season",40)` (community-worker/src/routes/reports.ts:147) and stores it (:171-173) — so `battle_reports.season` is NULL for all UI-created rows. Don't rely on it for scoring/joins.

Implications: the admin "mùa đang mở" setting must be a self-contained value (id string + vi label + zh label) stored server-side (D1/KV), not derived from season-registry. Recommend admin free-form: `id` (slug `^[a-z0-9][a-z0-9-]{0,39}$`), `labelVi`, `labelZh`; optional suggestion list seeded from the 2 registry scenarios (label vi only). Season ordering/“closed vs open” = equality with the open-season id; no need for compareSeasonIds. Keep season ≤40 chars to match reports.ts.
